## How I approach database engineering

- **Diagnose before changing:** establish a baseline, inspect waits, plans, Query Store, and workload behavior, then verify the result.
- **Treat SQL as engineering code:** source control, deployment reviews, repeatable scripts, validation, and rollback planning.
- **Build for reliability:** account for recovery, observability, retention, permissions, operational runbooks, and the developer experience.
- **Explain tradeoffs:** communicate what is proven in a test environment, what is not yet production-hardened, and what the next verification step is.
